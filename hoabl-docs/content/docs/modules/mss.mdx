## Apex classes

| Class | Description |
| --- | --- |
| `CampaignMetricsController` | A cacheable Aura controller that compares a Campaign's planned vs actual Enquiries, Leads, VCs, Applications and Bookings, along with planned/actual spend. For each metric it computes cost-per-unit (amount divided by count), flags whether the actual cost beat the planned cost with a CSS class, and computes a progress percentage capped at 100. Enquiries is special-cased to show 'N/A' for its planned value and cost since no planned-enquiries figure exists. |
| `CustomerPortal_CMSLaunchController` | Manages Launch-tab CMS content for the Customer Portal: investment carousel images, newsletters and video updates scoped to a specific Launch. getInvestmentCarouselImages() validates the Project Id and returns ordered CUST_PORT_Investment_Carousel_Image__c records with their linked file's download URL, name and size, while createInvestmentCarouselImage() validates the project, name and serial number before resolving the shared Customer Portal config and inserting the new carousel entry. |
| `CustomerPortal_LaunchContentProvider` | Supplies Launch-specific content for the Customer Portal: a launch alias (replacing the internal Launch name for customers), the carousel images shown on the Investment Detail page, and the background image used on the Investment listing page. It also returns RERA registration details (number, account number, supporting image and URL) per launch, capped at a 1,000-record retrieval limit to keep response payloads manageable. |
| `Ex_AddDiscountsDashboardController` | Backs the 'Add Discounts' dashboard shown on a Launch, exposing a getLaunchName() lookup and an addNewDiscount() method that builds a new (unsaved, mostly blank-valued) Discount__c record scoped to the launch for the LWC to populate and submit, alongside a placeholder LightningStudio() debug method apparently left over from component scaffolding. |
| `Ex_BankAPFsHandlerService` | Validates Bank APFs (Approved Project Financing records) to block duplicate APF numbers within the same RERA Phase. It groups incoming records by APF Number + RERA Phase key, queries existing records sharing those APF numbers, and adds a record error naming the conflicting APF number wherever a new or updated record collides with a different existing record in the same phase. |
| `Ex_BankAPFsTriggerHandler` | Trigger handler for Bank_APFs__c that filters to only records with both an APF Number and RERA Phase set, then delegates to Ex_BankAPFsHandlerService.validateDuplicateAPF() on insert, and on update re-runs the same check only for records whose APF Number actually changed to a new non-blank value. |
| `Ex_BankDSAHandlerServices` | Prevents a Bank from being linked to the same Project more than once via separate Bank_DSAs__c (Direct Selling Agent) records. It builds a map of Bank Id to Project Id from the incoming records, calls a duplicate-lookup helper, and adds a record error naming the conflicting existing DSA record whenever a Bank/Project pairing is already represented elsewhere. |
| `Ex_BankDSATriggerHandler` | Trigger handler for Bank_DSAs__c: on before-insert it filters to records that have both a Bank and Project populated and runs them through Ex_BankDSAHandlerServices' duplication check, and on before-update it re-validates records whose Bank/Project combination has changed, keeping the same-bank-same-project uniqueness rule enforced on every save. |
| `Ex_BankTransactionReceiptController` | Supports the bank-transaction receipt screen for a Project. getCompanys() returns the distinct set of Companies used by Bookings on the given Project (so the receipt form only offers relevant legal entities), and getPicklistValues() generically reflects any object/field's active picklist values given their API names, letting the LWC populate dropdowns without per-field Apex methods. |
| `Ex_CampaignBatchClass` | A scheduled batch that finds Active campaigns of type 'Daily' whose start date has arrived (or passed, excluding ones created that same day) and inserts a new Campaign_Performance__c record dated tomorrow for each one, effectively pre-seeding the next day's performance-tracking row so daily campaign metrics have somewhere to roll up into automatically. |
| `Ex_CampaignHandlerServices` | Creates Campaign_Performance__c tracking records for a given set of Campaign Ids. For 'Daily' performance type it inserts one row dated today per campaign; for 'One-Time' type it instead dates the row to the campaign's own StartDate, giving campaigns that only run once a single performance record tied to their actual run date rather than a recurring daily one. |
| `Ex_CampaignTriggerHandler` | On Campaign insert, splits incoming records into Active campaigns (triggering a 'Daily' performance record via Ex_CampaignHandlerServices) and campaigns whose Campaign_Performance_Type__c is 'One-Time' (triggering a one-time performance record keyed to the campaign's start date), so every new campaign automatically gets its first performance-tracking row created in the correct cadence. |
| `Ex_ChargeDetailsTriggerHandler` | On Charge_Detail__c insert, shares each new charge detail's parent Quotation with the appropriate users via Ex_ApexSharingManagementServices, then resolves and registers the related Opportunity Id for each shared record so Opportunity-level sharing rules can also pick up the new charge detail. |
| `Ex_ChargeDetailTrigger` | The Charge_Detail__c trigger (after insert only) that simply forwards new records to Ex_ChargeDetailsTriggerHandler.afterInsert() for apex-sharing setup. |
| `Ex_Clone_PaymentScheme` | Supports cloning a Payment Scheme from one unit type (Property_Type__c) to another within the same or a different Phase/Project. getUnitType() resolves a unit type's parent Phase and Project, and getPaymentSchemes() lists every Payment_Scheme__c already defined for that unit type, giving the admin a source scheme to copy milestones and charges from before applying them to the target unit type. |
| `Ex_CompanyBankAccountHandlerServices` | A future, callout-enabled method that registers a new Company Bank Account with the payment gateway as a sub-merchant. It loads the 'Create Sub Merchant Id' endpoint and base URL from Sub_Merchant_API_Details__c custom settings, pulls the Company's Key/Salt credentials, and (beyond this excerpt) posts the bank account details to the gateway so payments collected under that company can be routed to the correct bank account. |
| `Ex_CPLaunchHandlerServices` | Shares new CP_Launch__c records with the right Channel-Partner-Sourcing-Team hierarchy. processCPLaunchSharing() finds each record owner's Team_Member__c entry (scoped to the Channel Partner Sourcing Team for that launch) to resolve their Team Lead and Team Head, then (beyond this excerpt) inserts CP_Launch__Share records so those managers automatically see CP Launches owned by their team members. |
| `Ex_CPLaunchTriggerHandler` | Handler for the CP Launch trigger: before-insert and before-update (only for records whose Channel Partner or Launch changed) run duplicate-CP-Launch validation via Ex_CPLaunchHandlerServices, and handleCPLaunchInsertSharing() kicks off the Apex-sharing setup so new CP Launch records get shared with the appropriate sourcing team management chain. |
| `Ex_CreateCPLaunchController` | Backs CP Launch creation. getLaunchNames() lists every active Launch for selection, and getChannelPartners() returns the Channel Partners already associated with a given Launch via existing CP_Launch__c records, grouped by launch Id, so the creation UI can show which partners are already linked before adding a new CP Launch association. |
| `Ex_DigitalLeadHandlerServices` | Processes Facebook-sourced Digital Leads into Salesforce Leads/Opportunities. fbLeadProcess() loads a Digital_Lead__c's full ad-attribution payload (campaign, adset, ad, UTM parameters, GCLID/FBCLID click ids, CTI flag) for a single lead at a time and converts it into the corresponding Lead/Account/Opportunity records, recently modified to no longer require the matched Campaign to be Active__c. |
| `Ex_DigitalLeadShiftProcessingBatch` | A stateful batch that, once daily at 11 AM, releases Leads that were held overnight (11 PM–8 AM, non-shift hours) for CTI dialer processing: it finds not-yet-converted Leads flagged Held_For_Shift_Processing__c, flips that flag off and marks them Present_in_CTI_Dialer__c, and collects their Ids across all batch chunks (via Database.Stateful) so finish() can push the whole set to Convox at once — since the usual @future CTI push can't run from inside batch execute() context. |
| `Ex_DigitalLeadTriggerHandler` | On Digital_Lead__c insert and update, collects every record that isn't yet Executed__c (or just flipped back to not-executed) and passes those Ids to Ex_DigitalLeadHandlerServices.fbLeadProcess(), so a Facebook-sourced lead is processed into a Lead/Opportunity exactly once it's ready, and reprocessed if something resets its executed flag. |
| `Ex_DocumentTemplateTrigerHandler` | On Document_Template__c before-insert, resolves each template's Project (specifically its Registration Team Lead) and that project's Service Team / Loan Manager Team members, so downstream logic (beyond this excerpt) can route or notify the correct team when a new document template is added for a project. |
| `Ex_DocumentTemplateTrigger` | The Document_Template__c trigger (before insert, after insert, after update) routing to Ex_DocumentTemplateTrigerHandler's beforeInsert, afterInsert and afterUpdate methods for team-resolution and related automation. |
| `Ex_EditPropertyTypeinPropertyController` | A small lookup helper that returns every Property_Type__c (unit type) belonging to a given Phase, used by the 'Edit Property Type in Property' component to populate its unit-type selector. |
| `Ex_EditQuotation` | Backs quotation editing. getPriceListMapDetails() delegates to Ex_InventoryPriceManagementServices for the applicable price list, getAllPriceMapDetails() recomputes a quotation's full pricing (charges, car park price, discounts applied) into a raw numeric map, and getAllPriceInfoFormattedMap() converts those raw figures into currency-formatted display strings for the edit-quotation UI. |
| `Ex_FinanceTeamRefundDashboardController` | Backs the Finance team's refund dashboard. getRefundStatusList() reflects Case.Application_Case_Status__c's picklist values but explicitly excludes 'Sales Retention In-process' and 'Pending MSS Approval' from the filter options (since those statuses aren't relevant to Finance's refund queue), and getRefundList() returns the actual paginated list of refund cases matching the dashboard's selected filters. |
| `Ex_FormQuestionsTrigger` | The Form_Questions__c trigger (before insert, before update) routing to Ex_FormQuestionsTriggerHandler's beforeInsert and beforeUpdate methods, enforcing that a launch can't have two form questions both marked sequence 1 for the same restricted form type. |
| `Ex_FormQuestionsTriggerHandler` | Enforces a one-sequence-one-per-type rule for a launch's form questions. For the restricted form types (Awakening Form, JBP Form, Tell Us More), beforeInsert() checks whether that launch already has a Sequence__c = 1 question of the same type and blocks the insert with a clear error if so, preventing two 'first questions' from ever existing for the same form on the same launch. |
| `Ex_GenerateQuotation` | Backs quotation generation on an Opportunity. getOpportunityDetails() delegates to Ex_InventoryPriceManagementServices for the opportunity's pricing context, and checkPropertyPresentInLaunchDetails() verifies a specific property is actually part of the given launch's inventory (via Launch_Property__c) before allowing a quotation to be generated against it. |
| `Ex_getAllRERAPhaseDetails` | An inbound @RestResource endpoint (/getAllRERAPhases) returning every RERA_Phase__c record (RERA number, parent project, test-record flag) to an external caller, part of the same public-facing REST API surface giving an outside system read access to HoABL's regulatory project data. |
| `Ex_getPropertyType` | An inbound @RestResource endpoint (/getPropertyTypeAPI) that looks up a single Property_Type__c by Id (passed as 'hoabl_inventorybucketid' in the POST body) and returns its configuration, area and price range, validating that an Id was supplied and that a matching record exists before responding — the single-record counterpart to the bulk Ex_getAllPropertTypeDetails endpoint. |
| `Ex_IncentiveManagementServices` | Calculates and creates sales incentives for VC (video call) activity. incentiveForVds() builds a web of lookups across each manager's Opportunities, their related Meeting-Done Events, Applications and Bookings, cross-referenced against each Opportunity's Launch's configured Spot Incentive slabs, tracking already-awarded incentive keys (by user + opportunity + incentive combination) so the same incentive is never paid out twice for the same milestone. |
| `Ex_LaunchService` | Syncs Launch records to an external CMS/website. insertLaunch() and updateLaunch() are future, callout-enabled methods that load a Launch's public-facing fields (name, salt/key credentials, company name, area and price ranges, organic campaign Id) along with the active HOABL_CMS__c base URL setting, then push each launch to the external CMS via handleApiCall() so the public website's project listings stay in sync with Salesforce. |
| `Ex_LaunchTrigger` | The Launch__c trigger (after insert, update, delete) routing to Ex_LaunchTriggerHandler's afterInsert, afterUpdate and afterDelete methods to keep the external CMS in sync with launch changes. |
| `Ex_LaunchTriggerHandler` | On Launch update, compares every CMS-relevant field (name, test-record flag, salt/key, company name, area/price range, organic campaign Id) between old and new values and, if any of them actually changed (and the context isn't a test run), calls Ex_LaunchService.updateLaunch() to push the change to the external CMS — afterInsert similarly triggers the initial CMS sync for brand-new launches. |
| `Ex_managePaymentSchemeController` | Backs the payment scheme management screen for a Property Type. fetchProjectCharges() returns the active Property_Type_Charge__c records for a unit type ordered by charge bucket, and fetchPaymentScheme() resolves a Payment Scheme's full context — its Property Type, Wing, Phase, Project, project type and whether GST applies on the token amount — needed before the scheme's milestones can be edited. |
| `Ex_PrintQuotationController` | The primary Visualforce controller for printing a Quotation, deliberately marked without sharing so portal users can download their own quotation via CustomerPortal_Services (which does its own access check first). It assembles up to five separate charge-wrapper lists, milestone wrappers, multiple charge-detail groupings for different consideration categories, and applied discounts, giving the print template everything it needs to lay out the full quotation breakdown. |
| `Ex_PrintQuotationNewViewController` | A newer quotation-print controller that adds deviation support on top of the standard print: alongside the price list, payment schedule and milestone wrappers (reused from Ex_InventoryPriceManagementServices and Ex_PrintQuotationController), it carries a deviation list and before/after deviation maps so the printed quotation can show milestones that were modified from the standard schedule. |
| `Ex_PrintQuotationResidentialController` | A Residential-specific variant of the quotation print controller, using the same charge-wrapper/milestone-wrapper/charge-detail structure as Ex_PrintQuotationController but separating discounts into distinct 'benefits' and 'waiver' discount lists, reflecting a different discount categorization used for residential (versus plot) quotations. |
| `Ex_ProcessHandlerServices` | Validates that every Process__c (a marketing/outreach campaign-like record) has at least one Launch selected. duplicationForProcess() adds a record error naming the specific process type (e.g. 'Digital' or 'ATL') if Launch__c is blank on any record, and separately errors if the whole incoming batch collectively has no launches selected at all, ensuring a process is always scoped to real launches before being saved. |
| `Ex_ProcessTriggerHandler` | On Process__c before-insert, splits incoming records into Digital-type and ATL-type processes and runs each group through Ex_ProcessHandlerServices.duplicationForProcess() with the appropriate type label, so the launch-required validation message correctly names which kind of process is missing its launch. |
| `Ex_ProjectHandlerServices` | Houses Project-level automation, including a commented-out createBankAPFAndDSAForProjects() method that would have auto-generated a Bank_APFs__c and Bank_DSAs__c record for every combination of a new Project and every Bank in the org — since disabled, presumably because that many-to-many record generation proved unnecessary or too broad in practice; the active createProjectInCMS() method (referenced by the Project trigger) pushes new projects to the external CMS. |
| `Ex_ProjectService` | Syncs Project records to the external CMS, mirroring Ex_LaunchService's pattern. insertProject() and updateProject() are future, callout-enabled methods that load a project's public-facing location fields (street, city, state, pincode, latitude/longitude, altitude) along with the active HOABL_CMS__c base URL, then push each project to the CMS so the public website's project pages stay in sync with Salesforce. |
| `Ex_ProjectTranscriptController` | Backs the Project transcript download LWC. getFileContent() retrieves the latest ContentVersion's Base64-encoded file body for a given ContentDocument (enforced with WITH SECURITY_ENFORCED), used to download CSS call transcript files that were generated and attached to a Project by the separate Ex_CSSTranscriptBatch job. |
| `Ex_ProjectTrigger` | The Project__c trigger (after insert, update, delete) routing to Ex_ProjectTriggerHandler's afterInsert, afterUpdate and afterDelete methods; a before-insert hook referenced in a comment is not currently wired up. |
| `Ex_ProjectTriggerHandler` | On Project insert, pushes the new project to the external CMS via Ex_ProjectHandlerServices.createProjectInCMS() and also calls Ex_ProjectService.insertProject() — effectively syncing the new project through two separate integration paths — while an older createBankAPFAndDSAForProjects() call is commented out; on update, it detects changes to any CMS-relevant field (name, address fields, etc.) to decide whether a CMS update push is needed. |
| `Ex_PropertyFinalizingController` | Backs the Property Finalizing dashboard. getProperies() returns the Approved or Valid Quotations tied to a given Application, including each quotation's property sale status, carpet area, property code, configuration and tower/wing name, so the customer or rep can review and finalize one specific unit from among the quotations generated for that application. |
| `Ex_PropertyHandlerServices` | Generates a Property's Pricing List from its Property Type's configured charges. insertPricingList() finds every active Property_Type_Charge__c for the relevant property types where pricing is maintained 'At Property Level' (as opposed to maintained centrally at the type level), groups them by property type, and (beyond this excerpt) creates individual Pricing_List__c records for each new property so it has its own editable price breakdown from day one. |
| `Ex_PropertySelectionDashboard` | Backs the Property Selection dashboard. getProjectRecords() lists every Project for selection, and getProjectDetails() returns a selected project's Project_Type__c and its ordered Phase records, letting the dashboard progressively narrow from project to phase before a specific property is chosen. |
| `Ex_PropertyShorlistingController` | Backs the Property Shortlisting dashboard. getProperies() returns every Launch_Property__c under an Application's Opportunity's Launch with sale status, carpet area, code, configuration and tower/wing details, and getUserValid() checks whether the logged-in user is one of the launch's four leadership roles (Closing Head, Portfolio Head, Business Head or MSS Head) to gate access to the shortlisting dashboard to authorized leadership only. |
| `Ex_PropertyTriggerHandler` | On Property insert, for every new property that has a Property Type set, generates that property's own Pricing List from the property type's charges via Ex_PropertyHandlerServices.insertPricingList(); on update it tracks further property-type and booking-related changes for additional handling beyond this excerpt. |
| `Ex_PropertyTypeChargesHandlerServices` | Generates per-property Pricing Lists when a Property Type Charge is configured to be maintained 'At Property Level'. insertPricingList() collects the affected property types, finds every existing Property under each one, and (beyond this excerpt) creates a Pricing_List__c for each property so property-level charges cascade down to every unit of that type. |
| `Ex_PropertyTypeChargesTriggerHandler` | On Property Type Charge insert, filters to only charges configured as 'Pricing List At Property Level' and runs them through Ex_PropertyTypeChargesHandlerServices.insertPricingList() to cascade the new charge down to every property of that type; on before-update it blocks changing the Pricing_Maintained_At or Charge_Type fields after creation, since switching pricing models on an existing charge would leave already-generated pricing lists inconsistent. |
| `Ex_PropertyTypeServices` | Syncs Property Type (unit configuration) records to the external CMS, following the same future-callout pattern as the Launch/Project/Property CMS sync classes. insertPropertyType() loads each type's configuration, area and price range plus its parent project, and pushes it to the CMS via the active HOABL_CMS__c base URL so the public website's unit listings reflect current inventory. |
| `Ex_PropertyTypetriggerHandler` | On Property Type insert, pushes every new record to the CMS via Ex_PropertyTypeServices.insertPropertyType() (skipped during tests); on update, compares every CMS-relevant field (name, configuration, area/price range, parent project, test-record flag) between old and new to decide whether a CMS update push is actually needed. |
| `Ex_QRLaunchController` | A global, without-sharing Visualforce controller for the QR-code registration desk used at CP Meets and JBP sites. It reads recordId and launchName from the page URL parameters when scanned, and fetchLaunchName() separately resolves the launch's name by Id for cases (noted in the code) where the URL parameter failed to carry it through correctly on-site. |
| `Ex_QuotationApprovalAttachmentController` | A global, without-sharing Visualforce controller generating the quotation attachment shown during the quotation approval process, carrying the same extensive charge-wrapper, milestone-wrapper and multi-category charge-detail/discount structure as Ex_PrintQuotationController so the approver sees an identical breakdown to what the customer would ultimately receive. |
| `Ex_QuotationDateInvalidationBatch` | A scheduled, stateful batch that invalidates Valid/Approved Quotations once their 7-day BA2 (booking amount 2) payment window has fully elapsed without the required threshold being met, releasing the associated unit back to Available. It deliberately recalculates whether BA2 was paid on the fly (comparing Amount_Paid__c against the threshold) rather than trusting BA_Remaining_Amount__c/BA_2_Paid_Date__c, since those fields are only populated once a quotation is finalized, and uses a strict less-than comparison so the 7th day itself still counts as valid — fixing a previous off-by-one bug noted in its own comments. |
| `Ex_QuotationHandlerService` | Moves an Application into the 'Plots Proposed' stage whenever a new Quotation is created against it. updateApplicationStatusToPlotProposed() collects every Application referenced by the new Quotations, loads them, and sets their status, signaling that a specific plot/unit has now been formally proposed to the customer. |
| `Ex_QuotationTriggerHandler` | On Quotation insert, collects properties on quotations that are 'Pending for Approval' (so their reservation block time can be updated), shares each quotation's parent Opportunity with the right users, pulls the Opportunity Team details for sharing purposes, and calls Ex_QuotationHandlerService to move the related Application into 'Plots Proposed' status. |
| `Ex_RERAPhaseDetailsAPI` | An inbound @RestResource endpoint (/getRERAPhaseDetails) that looks up a single RERA_Phase__c by Id (passed as 'reraphaseid' in the POST body), validating the Id is present and the phase exists before returning its RERA number, parent project and test-record flag to the external caller — the single-record counterpart to the bulk Ex_getAllRERAPhaseDetails endpoint. |
| `Ex_RERAPhaseServices` | Syncs RERA Phase records to the external CMS, following the same future-callout pattern as the other CMS-sync service classes. insertRERAPhase() loads each phase's RERA number and parent project along with the active HOABL_CMS__c base URL, then pushes it to the CMS so RERA registration details stay visible on the public website. |
| `Ex_RERAPhaseTrigger` | The RERA_Phase__c trigger (after insert, update, delete) routing to Ex_RERAPhaseTriggerHandler's afterInsert, afterUpdate and afterDelete methods to keep the external CMS synced with RERA phase changes. |
| `Ex_RERAPhaseTriggerHandler` | On RERA Phase insert, pushes the new record to the CMS via Ex_RERAPhaseServices.insertRERAPhase() (skipped during tests); on update, compares every CMS-relevant field (name, RERA number, parent project, test-record flag) between old and new to determine whether a CMS update push is needed. |
| `Ex_RestGetAllProjectDetails` | An inbound @RestResource endpoint (/getAllProjectDetails/*) returning every Project's location details — latitude/longitude, altitude, full address, country — as a bulk feed for an external system such as a map-based listings integration. |
| `Ex_RestGetLaunchDetails` | An inbound @RestResource endpoint (/getLaunchDetails) returning a single Launch's details (name, salt/key, company, active flag) by Id, requiring the Launch Id in the POST body and returning a clear error if it's missing or the launch doesn't exist — the single-record counterpart to the bulk launch endpoint. |
| `Ex_RestGetProjectDetails` | An inbound @RestResource endpoint (/getProjectDetails/*) returning a single Project's location details by Id, validating the Project Id is supplied and the project exists before responding — the single-record counterpart to the bulk project-details endpoint. |
| `Ex_TeamMemberHandlerServices` | Manages Closing Team member availability eligibility for launch assignment. checkLaunchAvailabilityforClosingTeam() loads every other Closing Team member currently marked available for launch assignment (excluding the incoming records on an update, to avoid comparing a record against itself) so the caller can detect and prevent a conflicting state where a user ends up marked available on two different team assignments at once. |
| `Ex_TeamMemberTriggerHandler` | Prevents duplicate Closing-vertical team assignments. beforeInsert() identifies new Team Members in the Closing vertical with both a User and Team set (though the actual availability-conflict check call is currently commented out), and beforeUpdate() detects relevant changes (User, Team, or Launch_Availability__c) to flag records that need the same conflict check re-run. |
