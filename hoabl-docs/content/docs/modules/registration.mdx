## Apex classes

| Class | Description |
| --- | --- |
| `BookingBatchUpdate` | A batch job that iterates every Booking__c record one at a time and recalculates its total percentage paid by delegating to Ex_ReceiptHandlerServices.updateOnAccountMoneyBooking with the booking's (currently empty) receipt list. It runs with batch size 1, so each execute() call processes a single booking, and simply logs completion in finish() with no further notification or error handling. |
| `BulkDemandsReceiptsDashboardController` | Backs a dashboard LWC for bulk-downloading Demand and Receipt documents and emailing them in bulk. It exposes a cacheable fetchProjects() method for populating a project picker, a DemandWrapper inner class that carries a Demand__c plus pre-formatted currency strings for the UI, and a shared buildAuraHandledException helper that explicitly calls setMessage() so error text actually reaches the LWC instead of a generic 'script-thrown exception' message. |
| `cpPortal_Controller` | The large, shared Aura-enabled controller behind most Channel Partner portal components: it returns the logged-in portal User, the list of active Launches eligible for the CP portal, a CP's associated launches by community username, and lookups like the launch's company name from a CP PO Line Item. Because so many CP portal LWCs call into it, it acts as the de facto data-access layer for the whole CP portal experience, running without sharing so guest/community users can read the records they need. |
| `CustomerPortal_AliasContentProvider` | Supplies customer-facing display aliases for Projects and Launches so the Customer Portal can show a friendlier public name instead of the internal Salesforce record name. Its getProjectAliases() method reads every Project__c with a non-blank Customer_Portal_Alias__c and returns a map of Project Id to an AliasContent wrapper holding both the alias and the real name as a fallback, so the UI always has something to display even where no alias has been configured. |
| `customerPortal_CaseServices` | Creates and manages Support Cases raised from the Customer Portal. It maintains static maps translating a customer-facing L2 category (Update Profile, Payments related, Documents, Loan related, Others) into both a display label and an internal L1 category (Request/Query/Enquiry/Dispute), then createCustomerSupportCase() looks up the related Application, assigns the Case owner to the Booking's Service Manager (falling back to the Opportunity's Closing Manager), and sets origin, priority and status before inserting it. |
| `CustomerPortal_CMSLatestUpdatesCtrl` | Manages the 'Latest Updates' CMS tab, covering Newsletter and Video content plus the audience-targeting rows that decide which customers see which content. Content itself is decoupled from any Launch/Phase; instead, separate targeting rows pair a Launch and Phase (with Project derived from them) to a content item, and a customer only sees content whose targeting exactly matches their own Launch and Phase. It exposes DTOs for targeting input, project/launch/phase tree nodes, and reach (customer/investment count) estimates. |
| `CustomerPortal_CMSLaunchController` | Manages Launch-tab CMS content for the Customer Portal: investment carousel images, newsletters and video updates scoped to a specific Launch. getInvestmentCarouselImages() validates the Project Id and returns ordered CUST_PORT_Investment_Carousel_Image__c records with their linked file's download URL, name and size, while createInvestmentCarouselImage() validates the project, name and serial number before resolving the shared Customer Portal config and inserting the new carousel entry. |
| `CustomerPortal_DocumentServices` | Returns the customer-visible legal documents (Agreement For Sale, Allotment Letter, Deed of Conveyance, Possession Letter, Reservation Letter) tied to the logged-in portal contact's bookings. getDocuments() queries Documents__c records scoped to the contact's own bookings/applications/launches, resolves each one's public file-download link via CustomerPortal_FilePublicUrlHandler and its project display name via CustomerPortal_Services, and is explicitly flagged in its own source as needing refactoring due to null-pointer risk. |
| `CustomerPortal_GuestUserServices` | Exposes Aura methods callable by unauthenticated guest users on the public-facing Customer Portal site. createDigitalLead() looks up (or implicitly relies on) a 'Website Organic Campaign' tied to the given Launch and inserts a Digital_Lead__c record stamped with a full set of 'DirectWebsite' UTM/channel attribution values, giving marketing a consistent way to tag leads that originate from direct, non-campaign website traffic rather than a tracked ad source. |
| `CustomerPortal_InvestmentDetailsProvider` | Provides investment- and support-related details for the logged-in portal contact across their Applications. getContactSupport() determines which internal contact (name and phone number) should be shown as the customer's point of contact by finding the highest-stage Application the contact has reached, using a static map of launch-to-image URLs (sourced from CustomerPortal_SiteContentProvider) to also back image lookups used elsewhere on the investment details screen. |
| `CustomerPortal_KeyActionReportService` | Aggregate reporting service behind the Customer Portal's internal Key Action Report dashboard, running without sharing so an admin can see portal activity across every customer regardless of their own record access. getSummary() and related methods accept optional start/end date bounds (null meaning unbounded) and roll up stats like open vs closed Case counts, using shared status-bucket sets that mirror the logic in CustomerPortal_CaseServices, capped at a 5,000-row limit per query. |
| `CustomerPortal_KYCFormService` | Backs the Customer Portal's KYC form, covering up to five applicant slots (Primary through Fifth Applicant) with personal-details and property-details wrapper classes for the UI, plus constants for a post-submission feedback form (rating, free-text comment, 'most liked thing' questions) that is fired once a customer finishes the KYC flow, tagging form submissions as coming from the Customer Portal. |
| `CustomerPortal_LaunchContentProvider` | Supplies Launch-specific content for the Customer Portal: a launch alias (replacing the internal Launch name for customers), the carousel images shown on the Investment Detail page, and the background image used on the Investment listing page. It also returns RERA registration details (number, account number, supporting image and URL) per launch, capped at a 1,000-record retrieval limit to keep response payloads manageable. |
| `CustomerPortal_MilestoneServices` | Computes the ownership-journey milestones shown to a logged-in customer across all their Applications. getMilestones() pulls each Application together with booking-level checklist flags (DOC registration, possession readiness, AFS registration, balance-due and no-due checklists, KYC submission) and maps them through static milestone-name and milestone-label mappings built once in a static initializer, returning a per-Application ordered list of milestone DTOs for the portal's journey timeline component. |
| `CustomerPortal_PSFDashboardController` | Controller behind the internal Customer Portal PSF (price per square foot) updation dashboard. It fetches each Project's current PSF rows (district, state, status, previous PSF value) for an admin to review and update, while preserving the prior PSF value and the date it was set so a history of PSF changes is maintained rather than silently overwritten. |
| `CustomerPortal_Services` | A thin facade that resolves the customer-facing display name for a Launch or Project by checking the cached alias mapping first (lazily loaded from CustomerPortal_SiteContentProvider/AliasContentProvider) and falling back to the launch or project's own alias-fallback name, or null, when no alias has been configured — used wherever the portal needs to show a friendly name instead of the raw Salesforce record name. |
| `CustomerPortal_TransactionServices` | Returns the logged-in customer's approved payment transactions for the portal's transaction history view. getTransactions() queries Receipt__c records tied to Applications owned by the contact's person account, filtered to Approval_Status__c = 'Approved', including amount, payment mode and transaction Id, then enriches each with its project's display name before returning a list of CustomerTransaction DTOs. |
